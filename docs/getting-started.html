Getting Started

Run a full Tarcinapp stack locally in minutes. No Kubernetes required to start.

Prerequisites

  • Docker & Docker Compose — for the infrastructure stack (MongoDB, Redis, OPA)
  • Java 21 (or compatible JDK) — for the gateway
  • Node.js 20+ — for EPS and the GUI
  • Git — to clone the repositories

Minimum viable setup: Infrastructure (MongoDB + Redis + OPA) + EPS + Gateway. The orchestrator and GUI are optional for initial exploration.

Minimal Topology

This guide sets up the minimum stack to make authenticated API calls:

Browser / curl
  └── entity-persistence-gateway  :8081
        ↔ OPA                      :8181
        ↔ Redis                    :6379
        └── entity-persistence-service  :3000
              └── MongoDB          :27017
1

Start Infrastructure with Docker Compose

Clone the gateway repo (it contains a development docker-compose file) or create the following docker-compose.infra.yml:

version: "3.9"
services:
  mongodb:
    image: mongo:7
    ports: ["27017:27017"]
    volumes: [mongo_data:/data/db]

  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]

  opa:
    image: openpolicyagent/opa:latest
    ports: ["8181:8181"]
    command: ["run", "--server", "--addr", "0.0.0.0:8181", "/policies"]
    volumes:
      - ./policies:/policies:ro

volumes:
  mongo_data:

The ./policies directory must contain the Rego files from entity-persistence-gateway-policies:

git clone https://github.com/tarcinapp/entity-persistence-gateway-policies.git
# Copy the policies/ directory into your infra compose path
docker compose -f docker-compose.infra.yml up -d

Verify OPA loaded policies correctly:

curl http://localhost:8181/v1/policies
2

Start entity-persistence-service (EPS)

git clone https://github.com/tarcinapp/entity-persistence-service.git
cd entity-persistence-service
npm install

Create a .env file in the EPS directory:

NODE_ENV=development
HOST=0.0.0.0
PORT=3000
MONGODB_HOST=localhost
MONGODB_PORT=27017
MONGODB_DATABASE=tarcinapp

# Allow these kind values (comma-separated)
ENTITY_KINDS=book,author,chapter
LIST_KINDS=shelf
ENTITY_REACTION_KINDS=review,rating,bookmark

# Auto-approve records (set _validFromDateTime automatically)
AUTOAPPROVE_ENTITY=true
AUTOAPPROVE_LIST=true
AUTOAPPROVE_ENTITY_REACTION=true

# Default visibility
VISIBILITY_ENTITY=public
npm start

Verify:

curl http://localhost:3000/ping
# Expected: {"greeting":"Hello from LoopBack"}
3

Start entity-persistence-gateway

git clone https://github.com/tarcinapp/entity-persistence-gateway.git
cd entity-persistence-gateway

Create src/main/resources/application-dev.yaml:

app:
  name: my-books-app
  shortcode: books
  base-uri: /api/v1

  # Backend and OPA locations
  backend:
    host: http://localhost:3000
  opa:
    host: http://localhost:8181

  # JWT: use a test RS256 key pair or disable auth for dev
  auth:
    jwt:
      issuer: http://localhost
      jwk-set-uri: http://localhost/.well-known/jwks.json

  # Expose domain-specific routes for books
  kindAliasPaths:
    - alias: books
      name: book
      schema: '{"type":"object","required":["author"],"properties":{"author":{"type":"string"}}}'
    - alias: shelves
      name: shelf
    - alias: reviews
      name: review
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev

Verify the gateway is running:

curl http://localhost:8081/api/v1/openapi.json | head -c 200
4

Start tarcinapp-base-gui (optional)

git clone https://github.com/tarcinapp/tarcinapp-base-gui.git
cd tarcinapp-base-gui
npm install
npm run dev

Open http://localhost:5173. On the setup screen, enter the gateway URL http://localhost:8081 and a valid Bearer token. The UI will auto-build from the gateway's OpenAPI spec.

Generate a Dev JWT

For local development without Keycloak, generate a test RS256 token:

# Step 1: Generate a test key pair
openssl genrsa -out test_private.pem 2048
openssl rsa -in test_private.pem -pubout -out test_public.pem

# Step 2: Create a JWT payload (save as payload.json)
{
  "sub": "dev-user-001",
  "iss": "http://localhost",
  "aud": "my-books-app",
  "exp": 9999999999,
  "email": "dev@example.com",
  "email_verified": true,
  "resource_access": {
    "my-books-app": {
      "roles": ["tarcinapp.records.entity.admin"]
    }
  }
}
# Step 3: Sign with a JWT tool (e.g. node-jose, python-jwt, or jwt.io)
# Then use the resulting token:
export TOKEN="eyJhbGci..."
curl -H "Authorization: Bearer $TOKEN" http://localhost:8081/api/v1/books

Dev only: You must configure the gateway's app.auth.jwt.jwk-set-uri to serve your test public key, or configure a static public key in the gateway YAML. See the gateway README for dev JWT configuration options.

First API Request

With infrastructure, EPS, and the gateway running, make your first domain API call:

# Create a book
curl -X POST http://localhost:8081/api/v1/books \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "_name": "The Great Gatsby",
    "author": "F. Scott Fitzgerald"
  }'

# Expected: 201 Created with the full record including managed fields:
# {
#   "_id": "uuid-here",
#   "_name": "The Great Gatsby",
#   "_kind": "book",          ← injected by gateway
#   "_visibility": "public",  ← from VISIBILITY_ENTITY config
#   "_createdBy": "dev-user-001",  ← from JWT sub
#   "_validFromDateTime": "2024-...",  ← from AUTOAPPROVE_ENTITY
#   "author": "F. Scott Fitzgerald"
# }
# List books
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:8081/api/v1/books

# With pagination and search
curl -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8081/api/v1/books?limit=10&skip=0&s=gatsby"

Common Gotchas

1. JWT iss mismatch → 401

The iss claim in your JWT must exactly match the app.auth.jwt.issuer value in the gateway config. Even a trailing slash difference will cause all requests to fail with 401.

2. OPA returns 500 → policies not mounted

If the gateway logs show OPA returning 500, the Rego policies were not loaded. Verify:

curl http://localhost:8181/v1/policies
# Should list loaded policy IDs from entity-persistence-gateway-policies

3. Record not appearing in GET → auto-approve not set

If you create a record and it does not appear in GET /books, the record is in pending state. Set AUTOAPPROVE_ENTITY=true on EPS and restart, or manually approve by PATCHing _validFromDateTime to a past datetime (requires an admin token).

4. Gateway 503 on startup → EPS not ready

The gateway performs a startup health check against EPS. Start EPS before the gateway, or configure a startup delay / retry in the gateway settings.

5. 429 Too Many Requests → rate limiter

Default rate limits are intentionally conservative for production. For local dev, increase them in the gateway config:

app:
  inbound:
    rateLimiter:
      replenishRate: 100
      burstCapacity: 200

6. _kind value rejected → not in EPS allowed list

If you configure a kind alias in the gateway but see 422 INVALID-KIND on POST, the kind value is not in EPS's ENTITY_KINDS (or equivalent) environment variable. Add it and restart EPS.
